# Smart Metro Management System

# MetroX — Flask + SQLite (same UI as the GitHub Pages version)

This version keeps the original MetroX frontend design and page structure, but adds a Python Flask backend and SQLite database similar to the Hotel Management System project.

## Stack
- HTML / CSS / JavaScript — original MetroX UI
- Python + Flask — backend/API
- SQLite — users and persistent user data
- Werkzeug password hashing
- No `venv` required

## Run on Windows
1. Extract this ZIP.
2. Open the folder.
3. Double-click `run.bat`.
4. It installs the required packages, initializes SQLite, starts Flask, and opens:
   `http://127.0.0.1:5000/auth.html`

Manual commands:
```text
pip install -r requirements.txt
python seed.py
python app.py
```

## Database
The database is created at `instance/metrox.db`.

Stored server-side:
- users, roles, password hashes
- favorites
- journey history
- admin-added stations

Forgot password uses a **demo OTP** shown on the page; no real SMS/email is sent.

## Important
GitHub Pages can host the original static frontend, but it cannot run this Flask + SQLite backend. For the full-stack version, run the Flask app locally or deploy the Python backend to a Python-capable host.


## New modules (Smart Metro Management System)
| Module | Where |
|---|---|
| Admin Login | `auth.html` (admin@metrox.com / admin123) |
| Station Management (add / edit / delete) | Admin → Stations |
| Train Management (details + availability) | Admin → Trains |
| Route Management (source, destination, via stations) | Admin → Routes |
| Schedule Management (timings + frequency) | Admin → Schedules |
| Ticket Booking (date, train, passengers) | Book Ticket |
| Fare Calculation (source/destination based) | Fare Calculator + live fare in Book Ticket |
| Booking History (with cancel) | Booking History |
| Reports (bookings, revenue, passengers, top routes, CSV export) | Admin → Reports |

New SQLite tables: `trains`, `routes`, `schedules`, `bookings` (sample data is seeded on first run).
Background image: `images/metro-bg.svg` - replace it (or change the `url()` in `theme.css`) to use your own metro photo.

## Roles
| Menu | Admin | Passenger |
|---|---|---|
| Dashboard | admin dashboard with module cards | quick actions |
| Stations, Trains, Routes, Schedules | add / edit / delete | view only |
| Ticket Booking, Fare Calculator | yes | yes |
| Booking History | all bookings, cancel / delete | own bookings, cancel |
| Reports | yes | - |
| Dashboard | same page for both roles | same page for both roles |
The rules are enforced on the server (HTTP 403 for passengers), not only hidden in the page.

## New in this version
- **Yellow Line** (opened 11 Oct 2026): Poonamallee Bypass to Vadapalani, 11 stations, interchange with the Green Line at Vadapalani. Route finder, fares and booking work across all three lines (up to two interchanges).
- **Payment options** when booking a ticket: UPI, QR code, Card, Cash (demo, no real money). Card number and CVV are never stored.
- **Real QR codes** (generated by qr.py, no extra package needed) for the payment screen and the ticket.
- **Reports (admin):** today's and monthly collection, daily / weekly / monthly passengers and money, peak week of the month, payment mode split, top routes. "Load sample data" adds demo bookings (ticket ids start with DMO); "Clear sample data" removes them.
- **Trains page = "Where is my train":** search trains between two stations or tap any train. A train opens with its Running status, Station timetable (with the position of the train) and Trains between stations. Worked out from the schedules (not live GPS); admin changes timings in Schedules.
- **Add Train** (admin only, own menu item): add, edit and delete trains.
- The sample-data buttons were removed from Reports; old sample bookings (ticket ids DMO...) are removed on start.
